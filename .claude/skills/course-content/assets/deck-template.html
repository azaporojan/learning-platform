§1.1.1 — цели тестирования · 7–20 мин

Тестирование — это не только «искать баги»

Найти дефекты

Вызвать отказы (динамически) или найти дефекты напрямую (статически).

Оценить качество

Дать стейкхолдерам информацию для решения «выпускать или нет».

Снизить риск

Reduce the level of risk of inadequate software quality.

ISTQB CTFL Syllabus v4.0, §1.1.1 Test Objectives

Тестирование показывает наличие дефектов, но не их отсутствие

Program testing can be used to show the presence of bugs, but never to show their absence!
Edsger W. Dijkstra, Notes on Structured Programming (EWD249), 1970 · cs.utexas.edu/~EWD
На тесте ISTQB: вариант «prove that the software has no defects» — всегда неверный.

Ошибка человека становится дефектом, дефект — отказом

Error · mistake

в голове

Забыл, что результат дробный.

Defect · bug · fault

в коде

int interest = …

Failure

на экране

52 вместо 52.50

Root cause — почему человек ошибся (неясное требование, спешка), а не «строка 12».

После фикса: confirmation, потом regression

flowchart LR
  T[Tester: test fails] --> R[Defect report]
  R --> D[Developer: reproduce → diagnose → fix]
  D --> C[Tester: confirmation test]
  C --> G[Regression tests]
